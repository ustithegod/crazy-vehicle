## D-01. Большие целые числа и порядок проверок

Python допускает `10**400` как конечное целое число, но `float(10**400)`
вызывает `OverflowError`. Общие правила SPEC разрешают конечные `int`,
требуют конечных результатов и числовых атрибутов типа `float`.

В реализации валидация входного `int` отделена от преобразования результата
в `float`. Поэтому не меняется приоритет доменных проверок. Примеры:

```python
from walking_plane import (
    PlaneObstacleTooHigh,
    PlaneUnsupportedTerrain,
    WalkingPlane,
)

p = WalkingPlane("Топот", 1000, 2, 20, energy=0)
huge = 10**400

p.refuel(huge)                  # None; energy == 100.0
assert p.can_step_over(huge) is False

before = p.get_status()
try:
    p.move(huge, "air")
except PlaneUnsupportedTerrain:
    pass
assert p.get_status() == before

try:
    p.step_over(huge)
except PlaneObstacleTooHigh:
    pass
assert p.get_status() == before
```

`calculate_energy(huge, "road")` и `move(huge, "road")` при целых ногах
вызывают `ValueError` на вычислении. При повреждённых ногах `move` сначала
вызывает `PlaneLegsDamaged`. Конструктор с `mass_kg=huge`,
`leg_length_m=huge` или `max_speed_kmh=huge` вызывает `ValueError`:
соответствующий обязательный атрибут невозможно сохранить конечным `float`.

Просьба автору: подтвердить эту трактовку либо оформить иное решение через
артефакты контракта.

## D-02. Округление расчётной скорости до нуля

Минимальная положительная скорость `5e-324` разрешена конструктором.
Однако `5e-324 * 0.5 == 0.0`. Прямое деление на такую скорость выбросило бы
`ZeroDivisionError`, которого нет в контракте метода.

```python
from walking_plane import WalkingPlane

p = WalkingPlane("Топот", 1000, 2, 5e-324)
before = p.get_status()
try:
    p.move(5e-324, "rough")
except ValueError:
    pass
assert p.get_status() == before

# На дороге расчётная скорость остаётся положительной.
assert p.move(5e-324, "road") == 1.0
```

Реализован `ValueError` на этапе проверки конечности времени, после проверки
среды и исправности ног, до проверки запаса энергии. На чистый расчёт
`calculate_energy` малая скорость не влияет.

Просьба автору: подтвердить `ValueError` для нулевой расчётной скорости.
